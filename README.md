# amoCRM files -> Yandex Disk

Скрипт синхронизирует файлы карточки amoCRM в Яндекс.Диск.

CRM используется только на чтение: сделки, контакты, примечания, список файлов карточки и amoCRM Drive читаются через `GET`.
Записи идут только в Яндекс.Диск и локальную базу `data/sync.sqlite3`.

Основной источник файлов - `GET /api/v4/leads/{id}/files`. Это важнее обычных
`attachment`-примечаний, потому что туда попадают файлы карточки, включая файлы из
диалогов/мессенджеров, если amoCRM привязала их к сделке. `attachment`-notes
используются как запасной источник, с дедупликацией по `file_uuid/version_uuid`.

Аудиофайлы и голосовые по умолчанию пропускаются. Чтобы грузить и их:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py sync-by-field --include-audio
```

## Воронки

По умолчанию обрабатываются только эти воронки:

- Отдел продаж
- Юридический отдел
- Отдел завершения
- Успешно завершенные
- Техническая воронка
- Прогрев базы
- TG / Max - Боты
- [А7] TG / Max - Боты

Воронки `HH - агенты` и `TG - агенты` не входят в список и не обрабатываются.

Если нужно задать список жестко по ID:

```env
AMOCRM_ALLOWED_PIPELINE_IDS=867829,1312204,6942134,8993570,1657180,2154013,10915210,10948422
```

## .env

Файл `sinai-yd/.env` должен содержать:

```env
AMOCRM_BASE_URL=https://sinai24.amocrm.ru
AMOCRM_ACCESS_TOKEN=...
YANDEX_DISK_TOKEN=...
YANDEX_DISK_TEST_ROOT=test-CRM
YANDEX_DISK_SCAN_ROOT=test-CRM
YANDEX_CRM_FILES_SUBFOLDER=Файлы из CRM
MONITOR_INTERVAL_SECONDS=300
TG_BOT_TOKEN=...
ADMIN_ID=...
```

Для режима по полю сделки добавьте одно из двух:

```env
AMOCRM_YANDEX_FOLDER_FIELD_ID=123456
```

или:

```env
AMOCRM_YANDEX_FOLDER_FIELD_NAME=Папка Яндекс.Диска
```

## Тест последних сделок

Создать тестовые папки для последних 3 сделок и загрузить туда вложения:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py test-last --limit 3
```

Проверить без загрузки:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py test-last --limit 3 --dry-run
```

Тест конкретной сделки:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py test-leads --lead-id 32336655
```

## Синк по полю сделки

Скрипт берет путь из поля сделки и грузит файлы туда:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py sync-by-field
```

## Синк по событиям изменения поля

Основной рабочий режим: читать список событий amoCRM и реагировать только на
`Изменение поля "Папка Яндекс.Диска"`.

Одноразовая проверка последних 6 часов:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py sync-field-events --lookback-hours 6
```

Постоянный мониторинг каждые 5 минут:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py monitor-field-events --interval-seconds 300
```

## Боевой запуск

На VPS запускайте из папки `sinai-yd`:

```bash
python main.py
```

По умолчанию проверка идет каждые `300` секунд, то есть раз в 5 минут.
Интервал меняется в `.env`:

```env
MONITOR_INTERVAL_SECONDS=300
```

`main.py` делает два действия в каждом цикле:

- проверяет новые события изменения поля `Папка Яндекс.Диска`;
- проверяет папку Яндекс.Диска `YANDEX_DISK_SCAN_ROOT` на наличие новых папок сделок.

Если на Диске появилась папка, например `Сарафан от Драганчук (29210989)`,
скрипт найдет сделку по ID `29210989`, запишет owner-ссылку на эту папку в поле
`Папка Яндекс.Диска` в CRM и перенесет файлы сделки в подпапку `Файлы из CRM`.

Логи пишутся в:

```text
sinai-yd/data/logs/main_YYYY-MM-DD.log
```

Если заданы `TG_BOT_TOKEN` и `ADMIN_ID`, значимые события отправляются админу в Telegram:
запуск, обновление поля CRM, загрузки файлов и ошибки. Пустые циклы без изменений в Telegram не отправляются.

`main.py` ведет одно сообщение-панель в Telegram и редактирует его после каждого
цикла. В панели есть:

- подробный статус мониторинга;
- время последней проверки;
- сколько событий изменения поля найдено;
- сколько новых папок найдено на Яндекс.Диске;
- сколько задач обработано;
- сколько файлов загружено;
- сколько пропущено как уже загруженные;
- ошибки;
- кнопки `Обновить`, `Старт/стоп`, `Главное меню`, `Мониторинг`.

Если за один цикл найдено больше 5 новых изменений поля или больше 5 новых папок
на Диске, скрипт выполняет только первую задачу и редактирует панель:

```text
Новых изменений поля: X
Новых папок на Диске: Y
1 задача уже выполнена
CRM: ...
Диск: ...
Пробросить остальное?
```

Дальше в панели появляются кнопки:

- `Да, пробросить остальное` - обработает всю оставшуюся пачку, хоть 1000 сделок;
- `Нет, пропустить` - пометит оставшиеся задачи как пропущенные, чтобы бот не спрашивал повторно.

Для разовой проверки без бесконечного цикла:

```bash
python main.py --once
```

Для безопасной проверки без записи в CRM и без загрузки файлов:

```bash
python main.py --once --dry-run
```

Если Telegram-панель начала дублироваться, сначала остановите все лишние процессы
`python main.py`, затем пересоздайте известную панель:

```bash
python main.py --once --reset-panel
```

После этого запускайте один постоянный процесс:

```bash
python main.py
```

Для проверки конкретной сделки по значению поля:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py sync-field-leads --lead-id 29210989
```

Скрипт хранит обработанные события в `data/sync.sqlite3`, поэтому одно событие
не отработает повторно после перезапуска. Файлы тоже дедуплицируются отдельно:
если часть файлов уже загружена, повторный запуск добирает только недогруженные.

Поле сделки должно указывать на папку клиента. Скрипт сам создаст внутри нее
подпапку `Файлы из CRM`, если такой папки еще нет, и будет грузить файлы туда.
Название подпапки можно изменить:

```env
YANDEX_CRM_FILES_SUBFOLDER=Файлы из CRM
```

Первичный полный проход:

```powershell
python .\sinai-yd\sync_crm_files_to_yandex.py sync-by-field --all
```

Оптимизация для большого количества сделок: после обычного запуска скрипт сохраняет
последний `updated_at` в SQLite и дальше проверяет только сделки, изменившиеся после
прошлого прохода. Для принудительного полного прохода используйте `--all`.

## Формат значения в поле CRM

Рекомендуемый формат:

```text
disk:/test-CRM/32336655_Иванов Иван
```

Также можно указать просто путь:

```text
test-CRM/32336655_Иванов Иван
```

Можно использовать owner-URL из браузера Яндекс.Диска:

```text
https://disk.yandex.ru/client/disk/test-CRM/32336655_Иванов%20Иван
```

Публичные ссылки вида `https://disk.yandex.ru/d/...` не подходят для загрузки через API:
по ним нельзя надежно понять путь папки и право записи.

## Как создать поле в amoCRM

1. Откройте amoCRM.
2. Перейдите в `Сделки`.
3. Откройте любую сделку в нужной воронке.
4. В блоке полей сделки нажмите настройку/шестеренку полей или `Настроить поля`.
5. Добавьте новое поле.
6. Название: `Папка Яндекс.Диска`.
7. Тип: лучше `Ссылка`, если amoCRM дает такой тип; если нет, обычное `Текст`.
8. Сохраните поле.
9. Откройте настройки поля и скопируйте его ID, затем пропишите в `sinai-yd/.env`:

```env
AMOCRM_YANDEX_FOLDER_FIELD_ID=123456
```

Для проверки в сделку вставьте, например:

```text
disk:/test-CRM/32324147_Сарафан от Петров Олег Михайлович
```

или ссылку из адресной строки владельца Диска:

```text
https://disk.yandex.ru/client/disk/test-CRM/32324147_Сарафан%20от%20Петров%20Олег%20Михайлович
```
